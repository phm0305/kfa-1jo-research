# 밸류에이션 파트 엔진 요청서

대상: `members/valuation/engine_request.md`
적용 대상은 작업지시서의 분석 범위에 속하는 국내 상장 보통주다. 종목과 평가 기준일을 바꿔도 같은 입력 규격으로 밸류에이션을 실행할 수 있도록, 공통 엔진에서 아래 재무제표·주석·시장 데이터를 제공해 달라고 요청한다. 농심(004370) 2025년 사업보고서는 1차 검증 사례다.

## 3. 동종기업 재무제표와 주가

기업분석이 제안한 동종기업 종목코드와 선정 근거를 받고, 공통 엔진이 아래 자료를 종목별로 조회할 수 있도록 요청한다.

| 원천 | 추출할 계정·값 | 반환 형식·비교 조건 |
|---|---|---|
| **동종기업 손익계산서** | PER용 지배주주순이익, PSR용 매출액, EV/EBITDA용 영업이익 | 원, 평가 대상과 동일 실적기간·연결/별도 기준. 확정 실적과 전망치의 기준을 맞추고 전망은 별도 표기 |
| **동종기업 재무상태표·주석** | PBR용 지배주주자본, EV/EBITDA용 현금성자산·이자부채·리스부채·비지배지분 | 원, 동일 재무 기준일. 순차입금과 EV를 구성하는 계정 범위를 평가 대상과 일치시킴 |
| **동종기업 현금흐름표·주석** | EV/EBITDA용 유형자산 감가상각비·무형자산상각비 | 원, 영업이익과 같은 실적기간. PER·PBR만 비교할 때는 생략 가능 |
| **동종기업 주식수와 주가** | EPS·BPS용 유통보통주식수, 시가총액용 발행보통주식수, 비교일 확정 종가 | 주식수(주)·종가(원/주), 종목코드·거래소·통화, 재무 기준일과 주가의 실제 거래일, 출처. 평가 대상과 가격 기준일 일치 |

비교기업은 PER·PBR·PSR 비교를 P1, EV/EBITDA의 세부 계정 보강을 P2로 요청한다. 실적기간이나 가격 기준이 맞지 않는 표본은 중앙값 계산에서 제외하고 사유를 표시한다.

## 농심 독립 검증 사례

- 2025년 공시 기본 EPS는 연결감사보고서 주석 34의 분자와 가중평균 주식수로 재현했다.
- 2026-11-19 시험용 종가 342,000원으로 시가총액·PER·PBR을 계산했다. 공식 주가 연결의 완료 여부는 별도 확인이 필요하다.
- 증권사 2027년 추정치를 사용한 독립 계산도 수행했다. 통합 실행에서는 밸류에이션 자체 전망 가정과 평가 기준에 맞는 공통 입력을 사용한다.

## 공통 데이터 반환 원칙

1. 기존 15열 공통 표에 종목·항목·기간별 값 하나를 한 행으로 반환한다. 기준일과 실적기간, 단위, 연결/별도, 공시일·출처를 보존하고 원천 행의 `rid`와 출처 ID로 추적할 수 있게 한다. 15열 밖에서 별도 전달이 필요한 필드는 엔진 담당과 합의한다.
2. 원자료와 파생값을 구분하고 `단위`, `실적기간`, `실제 공개시각`, `가격 기준일`, `연결/별도`, `출처 ID/URL`, `수집 경로`를 추적 가능하게 한다.
3. 원천 신뢰도와 수집 경로(L1 공식 API / L2 라이브러리 / L3 파일 / L4 크롤링 / L5 수동)를 별개 필드로 기록한다.
4. 계산된 지표에는 기존 지표 표의 `metric_id(M#)`, 계산식, 입력 `rid`, 출처 ID, 기준일, 상태와 이유를 남겨 검증관이 재계산할 수 있게 한다.
5. 평가일 정규장 종가 산출 이후에 공개된 재무 수치는 해당 시점의 평가에 사용하지 않는다.
6. 결측은 `null`과 사유로 표시한다. 5개년을 채우기 위해 확인되지 않은 연도를 만들지 않는다.
7. API 키 값은 요청서와 로그에 기록하지 않는다.
8. 정식 실행의 결측값은 특정 종목의 임시 데이터로 채우지 않는다. 사용 가능한 종가가 없으면 시가총액·시장 배수·괴리율 등 종가 의존 지표에 미산출 사유를 표시한다. 전망이나 모형 평가에 필요한 입력이 확보되어 있으면 해당 단계는 진행한다. 모형별 입력이 부족하면 해당 모형의 주당가치에 미산출 사유를 붙인다.

## 리포트 4쪽 표·그래프 출력 요청

- **문제** — 공통 HTML 렌더러는 Markdown 문단과 불릿을 처리하지만 표 문법을 HTML 표로 변환하지 않는다. 이 때문에 5개 모형 판정표, 동종기업 비교표, Bear/Base/Bull 가치평가표가 웹 리포트에서 표로 표시되지 않을 수 있다.
- **생성 단계의 충돌** — 공통 출력 규칙이 파트 지시서 뒤에서 표·차트를 `표 필요` 문구로 바꾸도록 지정한다. 실제 4쪽에서 표를 내보낼 수 있도록 이 규칙에 밸류에이션 예외를 두거나 구조화된 출력 항목을 제공해야 한다.
- **요청 사항** — 공통 실행이 생성한 `report.html`의 밸류에이션 탭에서 5개 모형 판정표, 동종기업 비교표, Bear/Base/Bull 가치평가표를 실제 HTML 표로 표시하고, 유효한 종가 시계열이 있으면 주가 추이 그래프를 표시해 달라고 요청한다. 밸류에이션에 실제 표를 허용하고 Markdown을 변환하거나, 공통 계산 결과를 구조화해 템플릿이 직접 그리는 방식을 검토해 달라고 요청한다.
- **완료 기준** — 공통 실행 한 번으로 기존 4쪽에 표·그래프가 표시된다. 표의 행·열 순서, 숫자, 단위, 미산출 사유가 원본과 일치하고 문단·불릿 출력도 유지된다. 종가 시계열이나 계산값이 없으면 해당 영역에 결측 사유를 표시한다.
- **구현 참고** — `valuation.details`는 종가 시계열(`date`, `close`)과 비교기업·전망·가치평가 결과를 전달할 때 검토할 수 있는 제안 필드명이다. 현행 공통 템플릿에는 이 필드의 처리 기능이 없다. 로컬 검증에서는 저장된 리포트의 복사본에 별도 표시 코드를 적용했다.

## 엔진 담당 확인 요청

- 밸류에이션의 Bear/Base/Bull 가정(성장률·영업이익률·순이익 전환율, 필요 시 배당성향, 전망 기간·출처)과 센터장이 확정한 목표 배수를 공통 계산 단계에 전달할 수 있도록 요청한다. 선행 매출·영업이익·지배주주순이익·EPS·BPS와 모형별 적정가치 및 검증 근거를 4쪽에 반환한다. 밸류에이션이 먼저 제공하는 참고 배수와 센터장의 확정 목표 배수를 구분한다.
- `DATA_GO_KR_KEY` 연결 완료 여부와 가격 조회 실패 시 대체 경로
- 역사적 배수 계산 기능의 실제 구현 범위
- 검증관에게 전달 가능한 원천값·계산식·출처 ID의 현재 형태
- 위 P0/P1/P2 중 기존 엔진이 지원하는 항목과 신규 개발이 필요한 항목
