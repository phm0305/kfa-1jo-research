# 함정 기록

데이터를 받다가 헷갈리기 쉬웠던 곳을 적어 둡니다. 항목마다 무엇이 헷갈리는지, 틀렸으면 결과가 어떻게 됐을지, 어떻게 막았는지를 씁니다.

## 1. DART 주식총수 현황: "발행할 주식의 총수"와 "발행주식의 총수" (2026-11-20)

**무엇이 헷갈리나.** DART 주식총수 현황 API(`stockTotqySttus`)의 보통주 줄에는 이름이 비슷한 칸이 두 개 있습니다. `isu_stock_totqy`는 정관이 허락한 발행 한도(사업보고서 표의 Ⅰ. 발행할 주식의 총수)이고, 실제로 발행된 주식수는 `istc_totqy`(Ⅳ. 발행주식의 총수)입니다. 칸 이름의 `isu`(issue)만 보면 앞의 칸이 발행주식수처럼 보입니다.

**틀렸으면.** 농심(004370) 2025 사업보고서에서 `isu_stock_totqy`는 12,000,000주, `istc_totqy`는 6,082,642주입니다. 한도를 발행주식수로 썼다면 주식수가 약 2배로 부풀고, 그 주식수로 나누는 EPS·BPS는 약 절반, PER·PBR은 약 2배가 됩니다. 숫자 대조는 "데이터 묶음에 있는 값과 같은가"만 보므로, 묶음에 잘못 들어간 값은 대조를 통과합니다.

**어떻게 막았나.**
- `research-center/market.py`의 `share_records()`는 `istc_totqy`(발행), `tesstk_co`(자기주식), `distb_stock_co`(유통)만 읽습니다. 코드에 두 칸의 뜻을 적어 두었습니다.
- DART의 유통주식수가 발행주식수 − 자기주식수와 다르면 주식수를 쓰지 않고 "주식수 없음"으로 남깁니다. 한도 칸을 잘못 읽으면 12,000,000 − 248,454 ≠ 5,834,188이 되어 여기서 걸립니다.
- 테스트(`test_market.py`)의 가짜 응답에 한도 12,000,000을 함께 넣고, 결과가 6,082,642인지 확인합니다.
- 농심 값은 사업보고서 원문 표(Ⅳ 6,082,642, Ⅴ 248,454, Ⅵ 5,834,188)와 대조했습니다.

## 2. 네이버(FinanceDataReader) 종가와 한국거래소 정규장 종가 (2026-11-20, 원인 미확인)

**무엇이 헷갈리나.** FinanceDataReader는 국내 종목 시세를 네이버 차트 데이터(`fchart.stock.naver.com`)에서 받습니다(설치된 0.9.202 코드에서 확인). 이 "종가"가 한국거래소 정규장(15:30) 종가와 다른 날이 있습니다.

**관찰한 것 (농심 004370).**
- 2025-08-27 ~ 2026-11-19의 300거래일을 네이버 증권 일별 시세와 Daum 금융 일별 시세로 비교했습니다. 종가가 다른 날은 44일이고, 모두 2026-09-14 이후입니다. 그 전에는 다른 날이 없습니다. 예: 2026-11-19 네이버 345,000 / Daum 342,000, 2026-11-18 네이버 354,500 / Daum 352,500.
- 네이버가 함께 주는 "전일 대비"로 거꾸로 계산한 전일 종가는 300일 모두 Daum 종가와 같았습니다. 즉 네이버도 등락률의 기준으로는 Daum과 같은 종가를 씁니다.
- 2026-11-19 네이버 실시간 시세 응답에서 종가 칸(345,000)이 넥스트레이드 애프터마켓(20:00 마감)의 마지막 가격(`overPrice` 345,000)과 같았습니다. Daum 응답은 정규장 거래량(22,901주)과 전체 거래량(23,384주)을 따로 줍니다.
- 연말 종가 2023-12-28, 2024-12-30, 2025-12-30은 두 곳이 같습니다.

**원인: 미확인.** 위 관찰로 보면 네이버 종가가 2026-09-14 무렵부터 넥스트레이드 애프터마켓까지 포함한 마지막 가격으로 바뀌었고, Daum 값이 한국거래소 정규장 종가라고 추측합니다. 그러나 한국거래소 원자료와는 대조하지 못했습니다(FinanceDataReader의 한국거래소 경로는 응답이 비어 실패). 하루(11/19)의 넥스트레이드 가격 일치만으로 원인을 확정하지 않습니다.

**틀렸으면.** 괴리율과 PER·PBR은 한국거래소 정규장 종가 기준이어야 합니다. 2026-11-19 기준으로 345,000과 342,000은 약 0.9% 차이가 나고, 그만큼 배수와 괴리율이 달라집니다.

**어떻게 막았나.** 2a 커밋(5189c73)의 현재 주가는 네이버 값이었습니다. 2b에서 FinanceDataReader 호출을 지우고, 공식 API(5번)가 연결될 때까지 주가는 "공식 API 연결 전, 주가 없음"으로 남깁니다. 원인 확인은 공식 API 값과 한국거래소에서 직접 본 종가를 대조한 뒤 이 항목에 적습니다.

## 3. Daum 금융 시세는 Referer를 꾸며야 열림 (2026-11-20)

**무엇이 헷갈리나.** 2번 비교에 쓴 Daum 금융 일별 시세 주소는 브라우저에서는 보이지만, 프로그램이 그냥 부르면 막히고 요청에 Daum 페이지에서 온 것처럼 Referer 머리글을 꾸며 넣어야 열립니다.

**틀렸으면.** Referer를 꾸미는 것은 사이트가 일부러 걸어 둔 제한을 우회하는 일입니다. 값이 정규장 종가처럼 보여도 공개 레포의 수집 코드에 넣을 수 없습니다.

**어떻게 막았나.** Daum은 수집 출처로 쓰지 않습니다. 2번의 Daum 값은 하루 비교용으로만 남깁니다.

## 4. 네이버 차트 데이터는 robots.txt가 전부 막음 (2026-11-20)

**무엇이 헷갈리나.** FinanceDataReader가 국내 시세를 받는 `fchart.stock.naver.com`은 라이브러리로 부르면 잘 받아지지만, 그 사이트의 robots.txt는 `User-agent: *` / `Disallow: /`로 모든 자동 수집을 막고 있습니다(2026-11-20 직접 확인).

**틀렸으면.** 잘 받아진다는 이유로 쓰면, 사이트가 금지한 자동 수집을 1조 레포가 조원 5명의 PC와 Colab에서 반복하게 됩니다.

**어떻게 막았나.** 1조 레포에서 FinanceDataReader를 뺐습니다(`market.py`의 호출, Colab 노트북 설치 줄).

## 5. 주가 출처 계획: 공공데이터포털 "금융위원회_주식시세정보" API

- 현재 종가와 연말 종가를 포함한 주가 줄 전체를 이 API 하나에서 받습니다. 수집 방법 1단계(공식 API), 신뢰도 상.
- 키는 `.env` 또는 Colab Secrets의 `DATA_GO_KR_KEY`. 키가 없거나 호출이 실패하면 다른 출처로 넘어가지 않고 "주가 없음"으로 남기며, EPS·BPS는 계속 계산합니다.
- 연결할 때 할 일: `market.py`의 연말 종가 함수 `pick_closes()`(지금은 호출하는 곳 없이 테스트만 있음)를 다시 씁니다. 그리고 2b에 넣은 "입력이 확인 필요여도 값은 계산" 예외(상태만 확인 필요로 표시)를 지우고 엔진 관례로 돌아갑니다. 공식 API 값은 "확인 필요"가 아니어서 이 예외가 필요 없기 때문입니다.
- 연결 전에 실제 호출로 응답 모양과 발표 시차(오늘 부르면 며칠 자 종가까지 나오는지)를 확인하고, 7일 규칙과 부딪히는지 봅니다. 아직 확인 안 함.
- 연결 시점: 조원 폴더와 초대(5단계)가 끝난 뒤.
